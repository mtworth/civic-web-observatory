Methodology

Civic Web Index performs lightweight, transparent, homepage-only checks of public-interest websites. It records availability, machine-readability, hosting/DNS hints, and automated accessibility signals. It does not bypass bot protections, crawl private areas, or perform vulnerability scanning.

What gets crawled

For each domain, the crawler requests only: the homepage over HTTPS and HTTP, /robots.txt, /sitemap.xml, and /llms.txt. No deeper links are followed.

Crawler identity

Every request identifies itself with a transparent User-Agent:

CivicWebIndexBot/0.1 (+https://civicwebindex.org/bot; contact: hello@civicwebindex.org)

What it does not do

  • No proxy rotation or fake browser fingerprinting
  • No CAPTCHA solving or bot-challenge evasion
  • No login attempts or admin path probing
  • No aggressive retries; blocks are recorded, not bypassed

Scoring

Raw observations only. This dataset deliberately avoids collapsing signals into a single opaque score. Every field shown (HTTPS validity, TLS issuer, missing alt text, etc.) is a direct, individually verifiable fact about the domain at the time it was checked.

Data sources

This dataset covers government domains from the CISA .gov registry (cisagov/dotgov-data) and nonprofit domains from IRS 990 filings. Coverage expands over time.

Metric glossary

Every signal is a direct observation from a single homepage request. No inference, no scoring.

Availability & status

Collection status
ok — homepage returned a 2xx or 3xx response. dns_failed — domain did not resolve. http_error — server responded with a 4xx/5xx. captcha / bot_challenge / blocked_by_cdn / http_403 / http_429 — bot-protection response detected and recorded without bypass.
Block type
Classifies the specific blocking mechanism when status is not ok: CAPTCHA page, Cloudflare/CDN challenge, explicit 403 Forbidden, or 429 Too Many Requests.
Homepage status code
The final HTTP status code after following redirects.
Response time
Time in milliseconds from opening the TCP connection to receiving the complete response body, measured over a single request with a 10-second timeout.

HTTPS & TLS

HTTPS available
Whether the domain served a valid response over https://. Does not require a valid certificate.
HTTP redirects to HTTPS
Whether a plain http:// request is redirected to https:// before content is served.
TLS valid
Whether the TLS certificate chain is trusted, the hostname matches, and the certificate has not expired, as verified by Python's ssl module.
TLS issuer
The organization name from the certificate's issuer field (e.g. Let's Encrypt, DigiCert, Sectigo).
TLS days until expiry
Calendar days between the observation date and the certificate's notAfter field. Values under 30 are flagged as expiring soon.

DNS & hosting

Primary IP
First A record returned by DNS resolution of the bare domain.
ASN / ASN org
Autonomous System Number and registered organization for the primary IP, looked up via the RIPE/ARIN database. Indicates the network owner (e.g. Amazon, Cloudflare, a university).
Nameserver hint
Hosting or DNS provider inferred from NS record patterns (e.g. *.awsdns.com → AWS, *.cloudflare.com → Cloudflare). "unknown" if no pattern matches.
CNAME hint
CDN or platform inferred from CNAME records (e.g. *.azurewebsites.net → Azure).

Machine-readable files

robots.txt
Whether /robots.txt returned a 200 response with non-empty body. The crawler parses allow/disallow rules and records whether the homepage is permitted.
sitemap.xml
Whether /sitemap.xml returned a 200 response. Content is not parsed beyond detection.
llms.txt
Whether /llms.txt returned a 200 response. This is an emerging convention for sites to declare AI-indexing preferences, proposed at llmstxt.org.

Technology stack

Technologies detected
CMS platforms, analytics tools, CDNs, JavaScript frameworks, and server-side languages identified by matching 7,600+ Wappalyzer fingerprint patterns against the homepage HTML, HTTP response headers, and script URLs. Detection is probabilistic — a match indicates strong evidence, not certainty.

Static accessibility

These signals are extracted from raw HTML without executing JavaScript. They identify common structural issues, not WCAG compliance.

Has page title
Whether the HTML <title> element is present and non-empty.
Has html lang
Whether the <html> element carries a lang attribute. Required for screen readers to use the correct language engine.
Has main landmark
Whether a <main> element or role="main" is present. Helps assistive technology skip to primary content.
Has nav landmark
Whether a <nav> element or role="navigation" is present.
Images missing alt
Count of <img> elements without an alt attribute in the homepage HTML. Averaged across domains in aggregate views.
Inputs missing labels
Count of <input> elements not associated with a <label> via for/id or aria-label. Averaged across domains.
